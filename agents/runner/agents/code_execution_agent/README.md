# Code Execution Agent

The Code Execution Agent is a first-pass hybrid agent that combines the current ReAct toolbelt loop with an explicit Python runtime contract.

## What it does

- Inherits the ReAct agent's planning, explicit `final_answer`, and dynamic toolbelt behavior
- Injects a system prompt that tells the model to treat Python as the default orchestration layer for multi-step tasks
- Pre-adds `code_exec` to the toolbelt when that tool is available
- Gives the model an exact `mcp_client.py` template it can write into the sandbox workspace to call MCP tools programmatically from Python

## Current scope

This is intentionally a first slice, not the final architecture.

- The agent still uses the existing ReAct loop
- The runtime files are described and templated through the prompt; they are not auto-generated by the harness yet
- Direct MCP tool calls and code execution coexist, with Python recommended for larger or more compositional workflows

## Runtime contract

The prompt points the model at a per-trajectory task workspace under:

`/filesystem/.code_execution_agent/<trajectory_id>/`

Suggested task-side files:

- `main.py` - the script the model iterates on
- `mcp_client.py` - helper for calling MCP tools programmatically

## Why this shape

This PR slice is meant to prove the agent contract first:

- Python is the composition layer
- MCP is available programmatically from task-side code
- Direct tool calls remain available for fast one-off actions

If the contract works well, later iterations can move from prompt-provided templates to harness-generated runtime files and richer wrapper generation.
